# (팀 미션) 뉴스 요약 자동화 #  

------------  
매일 수많은 뉴스가 쌓이는 정보중에서 "내가 정말 놓치면 안 되는 중요한 키워드"나 "특정 주제"가 포함된 정보들을 요약된 내용을 모아서 볼 수 있는 시나리오입니다.  

✅ 목표  
*RSS 피드에서 자동으로 뉴스를 수집하고, AI로 요약한 후, 노션 데이터베이스에 저장하는 완전 자동화 워크플로우 구축*  
 
------------

                         관심 있는 기업 정보(뉴스)를 요약된 내용으로 받아보고 싶어서 만들었습니다.

## 📌  에러 처리  : 에러 처리 정책과 선택 이유

자동화 툴(Make.com)에서 에러 처리는 **"흐름이 끊기지 않게 하는 것"**과 **"문제가 생겼을 때 알림을 받는 것"**이 핵심입니다.  

### 에러 처리 정책

    본 시스템은 Make의 Error Handler 기능을 활용하여 모듈별 실패 상황에 대응합니다.
    에러 발생 시 시나리오 전체를 중단하지 않고 오류 유형에 따라 Resume / Ignore 방식으로 구분 처리합니다.


### 에러 핸들러 적용 모듈 및 정책

   1. 에러 알림 구조 설계
      
     에러가 발생해도 전체 워크플로우가 멈추지 않고, 나에게 이메일을 보낸 뒤 다음 단계로 넘어가는 구조.  
   
      🔹구조: [에러 발생 모듈] -> [에러 핸들러 경로] -> [Email 모듈] -> [Resume/Ignore]
   
   2. 에러 처리가 가장 필요한 핵심 모듈 (Top 2)
      
      🔹 OpenAI (Generate a completion): 가장 에러가 잦은 구간입니다. (API 호출 한도 초과, 서버 타임아웃, 부적절한 콘텐츠 필터링 등)  
      🔹 Notion (Create a Database Item): 네트워크 오류나 데이터베이스 속성 불일치로 실패할 수 있습니다.
   
   3. 에러 처리 적용 정책: Resume (기본값 대체)
      
        🔹 OpenAI 에러 발생 시 → Email 모듈 (나에게 알림) → Resume (기본값으로 다음 단계 진행)
     
          동작 방식:
           → OpenAI API 호출 실패 시 기본값으로 자동 대체
           → 이후 모듈(Notion 저장) 정상 실행 유지
        
          선택 이유:  
           → API 일시 장애 시 전체 시나리오 중단보다 기본값 저장이 데이터 손실 방지에 유리
           → 이후 수동 보정 가능
   
      🔹 Notion 에러 발생 시 → Email 모듈 (나에게 알림) → Resume (해당 뉴스 종료)
      
          동작 방식:
           → Notion API 호출 실패 시 Incomplete Executions에 해당 건 보관
           → 관리자가 직접 확인 후 수동 재실행 가능
           
          선택 이유:
           → Notion 저장은 핵심 기능으로 실패 시 데이터 손실이 직접 발생
           → Ignore 처리 시 해당 기사가 영구 누락될 위험
           → Resume으로 실패 건을 보존하여 복구 가능성 유지
         
   
   5. 이메일 알림 모듈 
          🔹적용 정책: Ignore
           
          🔹동작 방식:
           → 이메일 발송 실패 시 해당 오류를 무시하고 시나리오 계속 실행
           
          🔹선택 이유:
           → 이메일 알림은 부가 기능으로 발송 실패가 데이터 수집/저장에 영향 없음
           → 알림 실패로 인해 시나리오 전체가 중단되는 상황을 방지하기 위해 Ignore 선택
           → 알림 누락은 Make Scenario History로 대체 확인 가능
      
   6. Resume vs Ignore 선택 기준
      
           🔹Resume 선택 조건:  
              → 해당 모듈 실패 시 데이터 손실이 발생하는 경우  
              → 실패 건을 보존하여 이후 복구가 필요한 경우  
              → 기본값 대체로 시나리오 흐름 유지가 가능한 경우  
            
           🔹Ignore 선택 조건:  
              → 해당 모듈이 부가 기능인 경우  
              → 실패해도 핵심 데이터 수집/저장에 영향 없는 경우  
              → 실패 시 시나리오 전체 중단이 더 큰 손실인 경우  
   
   7. 에러 처리 정책의 한계  
   
            🔹현재 정책으로 대응 불가한 상황 : 스케줄 트리거 자체 미발동  
               → 에러 핸들러는 실행 중 오류에만 동작  
               → 트리거 미발동 시 어떤 핸들러도 작동하지 않음  
             
            🔹Make 플랜 Operations 전체 소진  
               → 시나리오 실행 자체가 불가  
               → 외부 모니터링 또는 수동 확인 필요  
             
            🔹대응 방안:
               → Make Scenario History 정기 확인  
               → Incomplete Executions 활성화로 실패 건 보존  
               → 추후 모니터링 시나리오 구성으로 자동 감지 보완 필요
